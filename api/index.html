    The names of the fields in the parameter metadata obtained from the MUST server.

    PLOTTED_SAMPLES_FIELD module-attribute ¶

    PLOTTED_SAMPLES_FIELD = 'plotted-samples'

    Row key for the (locally computed, not server-provided) sample count shown in ParameterMetadata.

    MAX_PLOT_POINTS module-attribute ¶

    MAX_PLOT_POINTS = 1000

    Maximum number of points per series drawn in the terminal plot. Rendering cost grows with the number of points.

    MAX_VISIBLE_OPTIONS module-attribute ¶

    MAX_VISIBLE_OPTIONS = 500

    Maximum number of parameters shown in the option list. Refilling the list with all ~70k parameters takes seconds.

    SHOW_ALL_MATCHES_ID module-attribute ¶

    SHOW_ALL_MATCHES_ID = '__show_all_matches__'

    Option id of the selectable hint shown when matches are truncated; selecting it loads the full match list.

    PARAMETER_CACHE_MAX_AGE module-attribute ¶

    PARAMETER_CACHE_MAX_AGE = timedelta(days=1)

    The parameter catalog is re-downloaded at startup only when the cache is older than this. Press 'r' to force it.

    HELP_KEYBINDINGS_PLACEHOLDER module-attribute ¶

    HELP_KEYBINDINGS_PLACEHOLDER = '<!-- KEYBINDINGS -->'

    Marker in the bundled help.md replaced with a table generated from MUSTApp.BINDINGS.

    Keeping the table generated (rather than hand-written in help.md) means it can't drift from the actual bindings: there is exactly one place (MUSTApp.BINDINGS) that defines what a key does.

    SEARCH_DEBOUNCE module-attribute ¶

    SEARCH_DEBOUNCE = 0.15

    Seconds to wait after the last keystroke before searching, so typing a word searches once instead of per key.

    SEARCH_CHUNK_SIZE module-attribute ¶

    SEARCH_CHUNK_SIZE = 4096

    Number of options scored per rapidfuzz call; each call blocks the UI thread until it returns (a few ms).

    SearchFields module-attribute ¶

    SearchFields = tuple[str, str, str, str]

    The option label, MIB name, the label's bracketed description, and PCF description_2 of one parameter.

    The bracketed description is also a substring of the label ("{mib_name} [{description}]"), but as its own, separately-anchorable field: an anchored regex like ^NC01_FRAME can otherwise never match it, since ^ on the label only ever matches at the mib_name's position (position 0), not at the bracket's.

    PLOT_DATE_FORM module-attribute ¶

    PLOT_DATE_FORM = 'Y-m-d H:M:S'

    plotext date format matching format_datetime(), for Plot.date_form() / Plot.xlim().

    PLOT_COLORS module-attribute ¶

    PLOT_COLORS = ('blue+', 'green+', 'red+', 'cyan+', 'magenta+', 'orange+', 'gray+', 'blue', 'green', 'red', 'cyan', 'magenta', 'orange', 'gray')

    Colors cycled across plotted series in the TUI plot; the first five match plotext's own default order. Deliberately excludes black/white, which can blend into the background. Names must be ones plotext.colorize() accepts (see plotext._dict.color_codes); it has no yellow or gold, unlike plotext's own default sequence.

    ParameterMetadata ¶

    ParameterMetadata()

    Bases: Static

    Widget to display metadata about a selected parameter.

    The metadata information is obtained from the MUST server and consists of:

    • Description: parameter mnemonic
    • Data Type: one of UNSIGNED_SMALL_INT, ...
    • First Sample: 'YYYY-MM-DD HH:MM:SS'
    • Last Sample: 'YYYY-MM-DD HH:MM:SS
    • Subsystem: one of TM, ...
    • Id:
    • Unit:
    • Parameter Type:
    • Name: mib name
    • Provider: name of the data provider

    Also shows plotted-samples, the number of data points fetched for the parameter's current plot. This is computed locally (not provided by MUST) and is reset to "–" whenever a new parameter is selected.

    Widget to display information about a selected parameter.

    • decim: Decimation factor
    • parval: Parameter value
    • subsys: Subsystem
    • valpar: Validity parameter
    • sptype: Special type
    • corr: Correlation
    • obtid: On-board telemetry identifier
    • darc: Data archive
    • endian: Endianness

    search_options async ¶

    search_options(search: str, mode: str, generation: int) -> None

    Search the ~70k options on a thread, so typing stays responsive.

    Being exclusive, every keystroke cancels the previous search while it is still waiting out the debounce. A search that is already running on the thread can't be stopped, so its result is dropped when the search text, the mode or the catalog changed in the meantime. option_list.loading (set by the caller before this worker starts) covers the debounce + match time with a spinner, so typing doesn't look like it did nothing -- the combined delay (debounce plus the regex/fuzzy match itself) is small but not instant.

    generation guards against a race on that shared loading flag: if this worker is cancelled, its finally can still run after a newer keystroke has already started a new worker and set loading back to True, since cancellation only takes effect at the next await, not synchronously. Clearing loading only when generation is still the latest one avoids an old, superseded worker turning the spinner off for a search that is still in progress.

    match_options ¶

    match_options(search: str, fields: list[SearchFields], mode: str) -> list[int]

    Return the indices into fields that match search.

    Modes:

    • "regex": all options where the case-insensitive regex matches one of the fields, in list order. Raises re.error for an invalid pattern.
    • "fuzzy": at most MAX_FUZZY_MATCHES options scoring above FUZZY_MIN_SCORE, best first.
    • "jump": the single best-scoring option (the first one when scores tie), or nothing for an empty list.

    The fuzzy score of an option is the highest partial_ratio over its fields, rounded like thefuzz does. This is a pure function, so it can run on a worker thread.

    must_tui.must¶

    REQUEST_TIMEOUT module-attribute ¶

    REQUEST_TIMEOUT = ClientTimeout(total=None, sock_connect=30, sock_read=30)

    Timeout for MUST link API requests: give up when connecting, or waiting for the next data, takes longer than 30 s.

    There is no limit on the total duration, so large but healthy transfers still complete. aiohttp's default (5 minutes total) made the TUI look hung when the server stalled.

    PAGE_SIZE module-attribute ¶

    PAGE_SIZE = 5000

    Samples requested per page from the paginated parameter data endpoint (its limit parameter).

    MUST link's REST API doesn't document a maximum for limit, so this is a guess, not a confirmed safe value. If the server caps it lower, pagination still works correctly (the cursor is followed regardless of how many samples an actual page turns out to hold) -- it would just mean more, smaller pages than expected.

    MAX_PAGINATION_PAGES module-attribute ¶

    MAX_PAGINATION_PAGES = 1000

    Safety limit on the number of pages get_parameter_data() follows via the paginated endpoint, guarding only against a runaway cursor (e.g. a server bug that never returns an empty one) -- not a limit MUST link documents or imposes itself. Deliberately generous (PAGE_SIZE * MAX_PAGINATION_PAGES == 5,000,000 samples at the current PAGE_SIZE): a flight telemetry series should never be silently truncated for a realistic query.

    search_parameters_async(name_pattern: str, data_provider: str | None = None, ctx: MustContext | None = None, use_cache: bool = True) -> list[NavigableDict]

    Search for parameters matching a pattern, returning all available metadata.

    get_parameter_data async ¶

    get_parameter_data(ctx: MustContext, data_provider: str, par_name: str, start: str, end: str, paginated: bool = False, truncated: list[bool] | None = None)

    Retrieve parameter data for a parameter from a data provider within a specified time range.

    The dictionary has the following structure:

    • content: A list of dictionaries with the following keys:

      • monitoringChecks: None or a dictionary of monitoring checks
      • metadata: A list with parameter metadata as a dictionary: id, name, description, subsystem, dataType,type, complete, unit

      • data: A list of dictionaries with the following keys:

        • date (str): Timestamp in milliseconds since epoch
        • value (int): Raw value
        • calibratedValue (float): Calibrated value or 'N/A'

    • cursor: The cursor for pagination, empty string if no more data is available.

    The plain (non-paginated) endpoint has no limit parameter of its own -- MUST link's REST API only accepts limit/cursor on .../data/paginated -- so limit is only sent when paginated is True.

    Parameters:

    Name Type Description Default
    ctx MustContext

    The MUST link context.

    		 required
    data_provider str

    The name of the data provider to retrieve data from.

    		 required
    par_name str

    The name of the parameter to retrieve data for.

    		 required
    start str

    The start time in 'YYYY-MM-DD HH:MM:SS' format.

    		 required
    end str

    The end time in 'YYYY-MM-DD HH:MM:SS' format.

    		 required
    paginated bool

    Whether to retrieve data in a paginated manner.

    		 False
    truncated list[bool] | None

    If given (only meaningful when paginated is True), True is appended to it when the MAX_PAGINATION_PAGES safety limit was reached while more data was still available (the cursor was non-empty), so the caller knows the returned data is incomplete.

    		 None

    Returns:

    Type Description

    A dictionary containing the parameter data.

    Example:

    {
    "content": [
        {
            "monitoringChecks": {
                "requiredSamples": 0,
                "useCalibrated": true,
                "checkInterpretation": "REAL",
                "checkDefinitions": [
                    {
                        "position": 0,
                        "type": "SOFT",
                        "lowValue": "string",
                        "highValue": "string",
                        "checkParameter": "string",
                        "checkValue": 0
                    }
                ]
            },
            "metadata": [
                {
                    "key": "string",
                    "value": "string"
                }
            ],
            "data": [
                {
                    "date": "string",
                    "value": 0,
                    "calibratedValue": "string"
                }
            ]
        }
    ],
    "cursor": "string"
}
